# Research behind Official ML for AI

Reviewed 30 October 2026. This is research from original project repositories, author documentation and papers; the authors were not contacted. These projects establish useful patterns, not a guarantee that any algorithm will achieve KartBlitz world-record pace.

## Five comparable implementations

1. **Peter Wurman and the Gran Turismo Sophy team.** Their agent learned competitive racing through deep RL using the actual game, with progress, contact and sportsmanship objectives. Racecraft required training scenarios involving other cars. KartBlitz implication: train with the game’s own dynamics, keep solo pace and traffic evaluation separate, and apply the one-defensive-move constraint during both training and deployment. Sophy used large-scale infrastructure; its compute budget does not transfer to one laptop. [Original author paper](https://sam.barrettnexus.com/publications/papers/nature22.pdf), [official project](https://www.gran-turismo.com/us/gran-turismo-sophy/project/).

2. **Yann Bouteiller’s TMRL / Trackmania pipeline.** TMRL separates experience collectors from learning, offers SAC/REDQ, and supports numerical speed with sensor/image histories. Its documentation demonstrates why progress rewards and observation history matter. KartBlitz implication: separate Node physics workers from the Python learner, retain previous controls and turning rate, and measure progress rather than reward speed alone. We can avoid screen capture because our own game exposes state. [Repository and pipeline documentation](https://github.com/trackmania-rl/tmrl), [author’s lab profile](https://initrobots.ca/en/team/yann-bouteiller).

3. **Linesight, associated with the public handles pb4git and Agade09.** Their Trackmania project uses an interface to control and inspect the real game. The repository reports human-level results and campaign-track record demonstrations. Its documented setup uses low-cost rendering to improve training throughput; its discrete-control/IQN ecosystem differs from our continuous PPO baseline. KartBlitz implication: actual-game access, honest recorded playback, and rendering only the inspected batch are valuable. Matching their visual presentation alone would not establish learning quality. [Repository](https://github.com/Linesight-RL/linesight), [installation and runtime configuration](https://linesight-rl.github.io/linesight/build/html/installation.html), [Agade09 profile](https://github.com/Agade09).

4. **James Herman, Jonathan Francis and the Learn-to-Race team.** L2R provides a simulator environment, a SAC baseline and explicit training/validation track separation. It supports expert demonstrations for initialization. KartBlitz implication: keep held-out evaluation starts and human laps, record lap times and completion separately, and make imitation optional. Their simulator and deployment requirements are not dependencies of this project. [Original paper](https://arxiv.org/abs/2103.11575), [repository and baseline](https://github.com/learn-to-race/l2r).

5. **Benjamin David Evans, Herman Arnold Engelbrecht and Hendrik Willem Jordaan.** Their trajectory-aided F1Tenth work evaluates TD3 with racing-line information and speed-profile learning, reporting improved high-speed completion on four maps. KartBlitz implication: a good reference trajectory can help initialization or reward experiments, while evaluation must include both speed and reliability. We do not make a strong centre-line reward the default, since KartBlitz also needs passing room. [Original paper](https://arxiv.org/abs/2306.07003), [author’s projects](https://bd-evans.com/).

## Decisions for this implementation

- **PPO is a starting baseline, not a research conclusion that PPO is best.** Several comparable projects use SAC, TD3 or distributional value learning. SB3 provides an established continuous-control implementation we can debug against. The environment contract permits a later SAC comparison. [SB3 PPO documentation](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html).
- Use numerical state, an actor with two 128-unit hidden layers, five controls and a 20 Hz decision rate over 60 Hz physics. These sizes/rates are project engineering choices to benchmark, not values established by the five papers.
- Extract the actual offline Kart/track functions into a generated headless factory. Browser parity tests must compare it with the running game. The old Python approximation is not the official training environment.
- Disable the legacy AI’s automatic heading correction for official policies, and apply the official policy’s fixed-step control path in both training and gameplay. Otherwise a learner could depend on scripted assistance.
- One shared learner gathers experience from multiple independent environments. Multiple environments are not multiple policy updates running unsafely on the same weights. Show one selectable batch and car, stream compact previews, and preserve real recorded attempt cohorts.
- Five separately fine-tuned actors are packaged per track. Difficulty targets, reward coefficients and defensive-encounter definitions remain tunable settings requiring game tests.
- Optional imitation initializes the actor, then PPO improves independently. Never treat arbitrary archived poses as trustworthy observation/action demonstrations without compatible geometry, state and control timing.
- Benchmark CPU and CUDA: SB3 explicitly notes that small PPO MLP workloads can suit CPU execution. GPU usage alone is not a throughput or quality metric.

The engineering checks are physics parity, Python/browser actor-output parity, real training/checkpoint resume, and measured browser races. The performance checks are completion, representative lap times, comparable human pace, contact and recovery. Training return alone does not certify a model.

Implementation update, 31 October 2026: at the user's request, environment version 2 uses standing starts just behind each track's real S/F gate for all training and evaluation attempts. Random-start practice and evaluation are no longer enabled. The actual game checkpoint/lap clock controls completion, and RL off-track penalties cover every physics tick including the stricter limit boundary. This supersedes the original randomized-start engineering choice; it does not change the research findings above.
